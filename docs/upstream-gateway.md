# 上游订阅管理

用户继续通过普通 Trojan/VLESS 入口连接；上游订阅只交给入口服务器上的独立服务。这个功能沿用现有用户权限、套餐总流量、倍率和限速，不新增客户端协议，也不要求旧节点重装。

## 开启

1. 备份数据库与当前部署文件。先在隔离环境验证。
2. 单独执行本功能的迁移：`php artisan migrate --path=database/migrations/2026_10_16_000001_create_server_upstreams_table.php --force`。它只新增 `v2_server_upstream`，不修改旧节点/用户表。
3. 设置 `UPSTREAM_GATEWAY_ENABLED=true` 并刷新部署的配置缓存。默认关闭。
4. 管理后台右下角出现“上游订阅”。页面位于原安全后台路径下的 `/upstreams`，复用管理员登录及现有 `authorization`。无须改动编译后的管理员或用户前端包。
5. 为网关准备独立 Trojan/VLESS 入口。在管理页选中入口、粘贴 HTTPS 订阅或支持的单节点 URI，设置更新周期、启用状态。多节点订阅填写准确节点名；单节点留空。
6. 首次保存下载一次性接入配置。按 V2bX 仓库 `experimental/upstream/README.md` 安装入口服务和专用出站路由。服务验证成功后显示“已连接”；验证完成后再在普通节点管理中向目标用户显示入口。

第一次仍需要配置入口服务器；后台不会凭订阅链接自动获得或安装一台转发服务器。之后的换订阅、定时更新、停用和状态查询都可在此页面完成。

## 管理行为

- 上游 URL/URI 使用面板 APP_KEY 加密存储；列表不返回链接、节点密码或接入令牌。备份/迁移时保留 APP_KEY。
- 每个入口绑定一个独立令牌，只保存其 SHA256；入口只能获取自己的上游。面板原有 server_token 不授权本接口。
- 编辑时链接留空保留原值。更换上游保留入口、用户凭据和原订阅地址。
- “立即更新”增加版本并要求服务重读。旧版本状态报告不能覆盖新的配置状态。
- 更新失败时服务保留上一份已验证配置；显式停用立即要求撤销转发。需要先停用才能删除绑定。
- “接入配置”会重置令牌，旧服务需安装新配置。普通订阅更换不需要重置令牌。
- 最近报告超过90秒显示服务离线。协议/状态来自入口确认；面板不会自行访问任意上游地址。
- 上游总流量和并发限制仍约束所有共享用户。这里控制的是用户经过入口的流量。

## API

管理接口位于原管理员前缀下的 `server/upstream`：GET `fetch`，POST `save`/`refresh`/`rotateToken`/`drop`。全部沿用 admin middleware。

入口接口：GET `/api/v1/server/Upstream/config?id=ID`，POST `/api/v1/server/Upstream/report?id=ID`，使用 `Authorization: Bearer <binding-token>`。HTTPS响应禁止缓存。仅返回这一入口的启用状态、配置版本、上游源、选择项和更新间隔。

## 回退

先停用绑定并停止新网关/入口服务，再关闭 `UPSTREAM_GATEWAY_ENABLED` 并刷新配置缓存。保留新增表作为备份即可；原有协议与订阅输出不依赖该表。只有确认不再需要所有绑定时才回滚该单独迁移。不要对全站执行不加范围的 migrate:rollback。

此前直接下发 Mieru 的试验分支已归档。本功能从原始基线开发，不依赖该试验。生产部署前仍须保留线上已有的自定义改动。

## 验证

`tests/Feature/UpstreamTest.php` 覆盖管理员权限、独立令牌、加密保存、版本竞争、停用/删除、入口丢失和功能开关。`tests/Integration/upstream-mysql.php` 只接受明确命名的空白临时数据库和非3306回环端口，验证真实 MySQL/MariaDB 的迁移、加密读写、唯一约束、版本更新及定向回滚；它不加载应用 `.env`。不得把生产数据库凭据用于这个测试。

客户端仍看到普通入口节点。后台“已连接”表示入口服务已通过上游 TCP 探测；上线前仍需从实际客户端网络验证入口证书、路由、UDP、容量和套餐扣费。
